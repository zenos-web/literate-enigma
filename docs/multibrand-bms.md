# 多品牌电池读取与显示

本次接入原有蚂蚁 ANT，以及极空、彦阳、嘉佰达保护板和蓝宝、陆行电量计。协议只读，所有出站请求在 BLE 边界再次经过白名单校验，不提供参数写入、校准或 MOS 控制。

| 设备 | 读取范围与限制 |
| --- | --- |
| 极空 JK | JK02 24S / 32S，300 字节校验和与布局识别。JK04 仅单体、均衡、运行秒数和按有效单体求和的总压，不编造电流、电量或容量。 |
| 彦阳 YYBMS | B 代 FC03 Profile / Summary / Status；旧 A 基础及扩展布局。旧 A 的电流方向和 SOC 未确认，不显示这些值。支持 FFE0 与两类 FEE9 模块。 |
| 嘉佰达 JBD | 经典 DD 03 / 04 / 05 基础、单体和型号读取，FF00 或 FFE0 通道。按需使用用户自己的六字符密码；真实 MAC 仅旧挑战登录需要。拒绝登录后停止自动尝试，不修改密码。 |
| 蓝宝 FA50 | 双表、自测总压、电流、功率、电量、设备与中继信息、报告压差。没有逐串网格、MOS 温度或 SOH。使用本机匹配码。 |
| 陆行 EM2APP / EM02 | 四块 FC03 请求及应答 CRC16 校验；自测总压、电流、功率、电量、最多 30 串、有效温度、循环和中继信息。剩余容量标明按 SOC × 额定容量计算；不用争议字段充当 SOH。 |

## 连接与显示

在「电池与 BMS → 连接设备」扫描并选择自己的设备，确认实际板型，再核对首批实时读数后保存。名称和服务只提供提示，通用 FFE0 不会自动选择 ANT。按 CoreBluetooth UUID 记住设备和手动指定的板型；原有 ANT UUID、名称和开关保持兼容。取消核对恢复原选择，核对期间的数据不进入记录。

模块密码和匹配码按设备隔离保存在本机 Keychain，不打印或导出。未命中通道会依次回退候选，先订阅通知，再串行发送只读请求；接收缓冲有上限，处理 BLE 分片、噪声、校验失败与超时。只有有效实时数据才能刷新连接状态，设备信息或辅助单体帧不延长过期总压的有效期。

卡片、实时摘要、详情、统计和导出共用带字段可用性标记的读数。未知值显示 `--`，真实零电量/零电流保留；没有电流或功率的设备不产生虚假的零峰值。卡片使用「极空」「彦阳」「嘉佰达」「蓝宝」「陆行」等品牌名称。缺少逐串数据时不伪造网格或压差，至少两串有效电压才计算单体压差；电量计可直接使用其报告的压差。

切换设备或协议时拆分记录，旧统计 JSON 保持可读。记录完整度使用单调时钟，断线间隔不计为有效采样；结束后冻结统计。电流符号按适配器说明显示：蚂蚁和电量计保留原厂符号，其他适配器以放电为正。

九号 4.3 寸的 JPEG 输出现与 5/7 寸 H.264 共用卡片画布，解决原先 JPEG 路径主动丢弃 BMS 图像的问题。卡片更新、移动和关闭都会使 JPEG 缓存失效，静止地图也能更新或清除卡片；不改变仪表端口、握手或视频协议。

极核 5 寸（SE+ / AE2 Pro）与 6.2 寸也接入同一卡片；启用卡片时 5 寸直传会话自动切换兼容转码，关闭后本次会话继续转码。独立 6.2 寸保留原协议，仅增加可选渲染入口。详见 [极核显示修复](zeeho-bms-display.md)。

## 验证与边界

- `bash Tools/test_bms.sh`：ANT 回归、JK02/JK04/彦阳 B 参考报文、JBD 公布报文、蓝宝合成双表和陆行 EM2APP 参考帧；分片、噪声、CRC、只读白名单、超时、字段缺失和记录兼容性测试。
- `bash Tools/test_ninebot_canvas.sh`：原生 macOS Core Image/JPEG 像素检查、四角布局、静止画面缓存更新/移动/清除、5/7 寸及极核 H.264 编解码回环。
- `bash Tools/test_zeeho_bms.sh`：生产极核输出配合内存仪表传输，验证运行中直传转为卡片转码、静止源画面的卡片更新/移动/关闭、启动前缓存与 AE2 竖屏。没有运行 iOS 模拟器。
- 用户反馈开发分支的九号 4.3 寸 BMS 画面现已正常显示。该反馈仅验证该显示链路，不代表这五类新增硬件全部完成实物联调。
- 新品牌/固件仍需分别核对电压、电流方向、容量、温度以及长期刷新。蓝宝合成帧和纯协议测试不构成实物连接证明。
